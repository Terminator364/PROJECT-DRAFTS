# MOTEUR BLESSING — MB-1 V4 : mise en œuvre partielle traçable

## Capacités ajoutées

* 24 contrats typés `GATE`, chacun associé à un sous-paramètre documenté (`FIXTURE_ID`, `DATA_QUALITY`, `MODEL_DOMAIN`, `PLAY_TIME_RULES`). Le contrôle `gate_readiness()` **ne peut pas** approuver une prédiction ; les attestations locales restent en quarantaine.
* 297 tâches persistantes triées par dépendance de travail. Les **24** contrôles de gouvernance sont les premiers, puis **55** mesures à définir autour d'historiques relativement simples, **206** mesures spécialisées, puis **12** descriptions de sorties dérivées. Ce tri n'est pas une mesure d'importance prédictive.
* Prototype de primitives sans entraînement, pure fonction sur historiques archivés fournis : buts GF/GA régulation, matches strictement terminés avant le gel, source publiée/capturée avant gel, jours écoulés depuis la fin du dernier match. Aucune capture indépendante garantie.

## Usage local standard Python 3.12+

Depuis la racine extraite de l'archive :

```bash
python -m unittest discover -s mb1 -p 'test_mb1_v4.py' -v
python mb1/contract_gate_v4.py --contracts
python mb1/contract_gate_v4.py --vault chemin/vers/coffre --fixture-id MATCH-001
python mb1/temporal_primitives_v4.py --target target.json --history history.json --lookback 5 --min-games 3
```

Le troisième appel rend `DO_NOT_ISSUE_VALIDATED_IC` même en présence de 24 pièces auto-déclarées. Le dernier est un **prototype éducatif/recherche** qui produit des métriques partielles ; son objet résultat porte toujours `model_scoring_authorized: false`.

## Principes conservés

Jamais de live, jamais de résultats du match analysé ni de score au-delà des 90 minutes réglementaires, UNKNOWN ≠ 0, risque de partage de primitives visible, aucun nouveau coefficient, comparaison baseline requise avant promotion. Les sources potentielles sont renseignées sans téléchargement massif ni assimilation de permissions. GitHub et Drive constituent des pistes de continuité indépendantes du dossier PC.

Lire `AUDIT_5_CYCLES_V4_20261016.md` pour les limites et `CHECKPOINT_V4_20261016.json` pour les empreintes et le suivi.
